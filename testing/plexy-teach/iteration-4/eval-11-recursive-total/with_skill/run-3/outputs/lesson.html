10 minutes · Python · One loop, repeated at different depths

Bring the child's answer back

Your goal: trace a recursive total through a nested list and explain exactly how a child's returned number becomes part of its parent's total.

You already know loops and function returns. We will use those ideas—not a new kind of arithmetic. Read the explanation for about six minutes, spend three minutes on practice, and use the final minute to retrieve the rule.

1. A nested list is one unfinished addition

For [2, 3, 4], a loop can add each number. For [2, [3, 4]], the second item is a list, not a number. First turn that smaller list into a number; then add that number.

total([2, [3, 4]]) = 2 + total([3, 4])
                       = 2 + 7
                       = 9

This is recursion: a function calls itself to solve a smaller part of the same problem. The outer call is the parent; the call it makes is its child. They run the same instructions on different lists.

The key: the child returns one number. The parent resumes where it paused and adds that number to its own subtotal. Calling the child alone does not perform that addition.

For this lesson, inputs are finite lists containing integers or more lists of that kind. Empty lists are allowed; lists that contain themselves and other types are out of scope.

2. Follow the pause and the return

This complete Python function uses a familiar loop. isinstance(item, list) checks whether the current item is a list.

def total(items):
    subtotal = 0
    for item in items:
        if isinstance(item, list):
            subtotal += total(item)
        else:
            subtotal += item
    return subtotal

Read subtotal += total(item) as: get the total of this child list, then add its returned number to my subtotal. While that child runs, the parent waits. The parent cannot finish this addition until the number comes back.

Every call has its own items and subtotal. The child's subtotal = 0 does not reset the parent's subtotal. The name is the same; the local value belongs to a different call.

Trace of total([2, [3, 4]]), in execution order
Active callWhat happensIts subtotal
Parent: [2, [3, 4]]Start with zero, then add the integer 2.0 → 2
ParentReach [3, 4]. Call total([3, 4]) and pause before adding its result.2, waiting
Child: [3, 4]Start a separate subtotal. Add 3, then 4.0 → 3 → 7
ChildIts loop is finished. return subtotal sends 7 to the waiting parent.7
ParentThe waiting statement now behaves like subtotal += 7.2 → 9
ParentIts loop is finished. Return 9 to whoever called it.9

Notice that return 7 finishes the child, not the parent. The parent still has work: use the returned value and continue its own loop. Also, return subtotal is after the loop, so a call includes all of its items before returning.

Where does it stop?

Integers take the else branch, so they need no further call. A list containing only integers finishes without making children. An empty list, [], skips the loop and returns 0. These are stopping cases: work that can finish without calling the function again.

On a finite input with no self-containing lists, following child lists eventually reaches one of those cases. Their answers then travel back to the waiting calls. An empty child contributes zero; it does not cancel numbers already added by its parent.

  3. State the outer call's subtotal just before it calls total([]) and just after that call returns.
Reveal A: the return chain and the reason

The parent calls total(item), waits for its number, and adds that number to its own subtotal. Each child has its own subtotal.

  • [3] adds one integer and returns 3.
  • [2, [3]] first has 2, then adds the child's 3 and returns 5.
  • The outer list first has 1, then adds that child's 5, reaching 6.
  • [] skips its loop and returns 0. The outer subtotal is 6 both before and after adding that zero. Finally, the outer call returns 6.

If you reset the outer total when entering [], you treated separate calls as though they shared one local variable. If you got the correct final number by mentally flattening the list, still check that you can explain the intermediate return of 5: that is the recursion skill.

B. Diagnose a tempting mistake

Keep the function unchanged except for this branch:

if isinstance(item, list):
    total(item)             # no addition here
else:
    subtotal += item

Predict what this changed function returns for [2, [3, 4]]. Explain whether the child still runs, where its answer goes, and the single statement that repairs the result.

Reveal B: computing is not collecting

It returns 2. The child still runs and returns 7, but the parent ignores that number. The child's separate subtotal does not automatically change the parent's subtotal.

Repair the branch with subtotal += total(item). That keeps the parent's existing 2 and adds the child's 7. Replacing the subtotal with the child's answer would lose the 2.

4. The rule to keep

Add integers directly. For a child list, ask the same function for its total and add the returned number. Each call returns its own subtotal after its loop finishes.

The essential limit: this function assumes only integers and finite nested lists, with no containment cycles. It does not validate arbitrary input. A deeply nested input can also exceed Python's recursion limit; this lesson teaches the return mechanism, not handling unlimited depth.
