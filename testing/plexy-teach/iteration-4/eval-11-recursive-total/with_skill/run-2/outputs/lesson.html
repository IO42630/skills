A recursive total is a returned subtotal

Your goal: trace a total through a nested list and explain exactly how a child call’s answer gets added to its parent’s total.

Spend about 2 minutes on the idea, 4 on the worked trace, 3 on practice, and 1 on the takeaway. Use paper for your predictions; reveal each answer only after trying.

1. Keep the loop; let another call handle a list

For a flat list like [3, 4], you already know the method: start at zero, add each number, return seven. For [2, [3, 4]], the second item is a list, not a number. First get that list’s total. Then add the returned number.

The same function can do that smaller job. Calling a function from inside itself is recursion. Here, the outer call is the parent, and the call it makes for the inner list is the child. These names describe their relationship, not different functions.

Each call owns a separate local total. The parent waits at the call, keeping its current total. The child computes a number and returns it. Only then does the parent add that number and continue its loop.

We will use finite, non-circular Python lists containing only integers or more lists, with modest nesting depth. The job is to add every integer, not to count the lists.

def nested_total(items):
    total = 0
    for item in items:
        if isinstance(item, list):
            total += nested_total(item)
        else:
            total += item
    return total

isinstance(item, list) checks whether the current item is a list. A number is added directly; a list is passed to a new call. return total is after the loop, so the call processes all its items before returning.

2. Watch the return become a number

Trace nested_total([2, [3, 4]]). The labels below distinguish two calls of the same function.

The decisive line in the parent is:

total += nested_total(item)

Once the child returns, the right-hand side has the value 7. For this step, the effect is total += 7. The child did not change the parent’s total from afar. Its returned value is what connects the two calls.

Why doesn’t it call itself forever?

A call only makes another call when it meets a list. The child [3, 4] contains only numbers, so it makes no further calls. An empty list [] also makes no calls: its loop runs zero times and it returns its starting total, 0. These are the stopping cases; no separate “if empty” line is needed.

For our finite, non-circular input, following inner lists eventually reaches such a stopping case. Returns then carry the subtotals back outward, one waiting parent at a time.

3. Retrieve, then change the input

A. Explain the connection

The parent’s total is 2 when it calls the child. The child returns 7. What happens to the parent’s total, and which operation causes it?

Reveal the connection

The parent’s total becomes 9 because the parent executes total += nested_total(item) using the returned 7. Merely computing seven in the child does not update the parent; adding the return value does.

B. Trace a changed case

nested_total([1, [2, []], 3])

Predict the final result. Then write three short traces: the outer call’s total after each item, the child’s total after each item, and the empty list’s return. Where does the outer call resume after the child returns?

Reveal the trace and reasoning
  1. The outer call starts at 0, adds 1, and waits with total 1 while [2, []] is processed.
  2. The child starts at 0 and adds 2, reaching 2. It calls the function on [].
  3. The empty-list call starts at 0. No items means no additions; it returns 0.
  4. The child adds that returned 0, staying at 2. Its loop ends and it returns 2.
  5. The outer call resumes at the waiting addition: 1 + 2 = 3. It then continues to its next item, 3, reaching 6, and returns 6.

Outer totals after each item: 1 → 3 → 6. Child totals after each item: 2 → 2. Empty list’s return: 0. The later 3 is not lost: the parent continues its loop after receiving the child’s answer.

C. Find the missing connection

Suppose only the list branch changes to this:

if isinstance(item, list):
    nested_total(item)  # No addition here.
else:
    total += item

For [2, [3, 4]], what would the outer call return? Explain what happens to the child’s answer, then write the repaired line.

Reveal the diagnosis

The outer call returns 2. The child still computes and returns 7, but the parent does nothing with it. Calling the function is not the same as adding its result.

Restore total += nested_total(item). This makes the child’s subtotal contribute to the parent’s total.

If your prediction differed, locate the first step where your totals diverged. In particular, check whether you gave each call its own total and added each returned value in the caller.

4. The rule to keep

Add numbers directly. For a list, ask another call for its subtotal, then add that returned number. Return your own total only after your loop finishes.

This version assumes only integers and lists. A list containing itself would never reach a stopping case, and very deep nesting can exceed Python’s recursion limit. Keep these practice inputs small; this is a teaching function, not a general-purpose input validator.
