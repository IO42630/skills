10-minute lesson · Python · Paper or a place to jot answers

A recursive call returns a number. Its caller must use it.

Your goal: trace a total through a nested list and explain how a smaller list’s answer becomes part of the outer answer.

You already know loops and function returns. We will use those exact ideas: a function can call itself, and each call has its own local variables. We assume finite lists containing only integers and other lists, with no list containing itself.

1. Keep the familiar loop · 1 minute

For a flat list, a loop adds each integer to a running total. In [2, [3, 4]], one item is a list rather than an integer. To add that item’s contribution, first ask for its total. That request uses the same function on a smaller part of the input.

That is recursion: a function calling itself. It does not mean sharing one running total across all calls. Think of the inner call as an ordinary function call that will hand back a number.

For each item: add the integer, or get the nested list’s total and add that returned number.

2. Watch the return travel upward · 4 minutes

This complete Python function implements that rule:

def nested_total(items):
    total = 0
    for item in items:
        if isinstance(item, list):
            child_total = nested_total(item)
            total += child_total
        else:
            total += item
    return total

answer = nested_total([2, [3, 4]])  # 9

isinstance(item, list) checks whether the current item is a list. If it is, the call nested_total(item) computes a number before that number can be assigned to child_total. The next line adds it. Otherwise the item is an integer, so the loop adds it directly.

Call the outer invocation the parent and the invocation it starts the child. These are labels for calls, not different functions.

  1. Parent starts with [2, [3, 4]]. Its own total is 0. The first item is 2, so its total becomes 2.
  2. Parent reaches [3, 4]. It calls nested_total([3, 4]). The parent pauses while this child computes an answer. The parent’s total remains 2; it is not reset.
  3. Child starts with its own total = 0. It adds 3, then 4: 0 → 3 → 7. These changes belong to the child, not the parent.
  4. Child executes return total. The number 7 goes back to the waiting parent. In the parent, child_total now receives 7.
  5. Parent resumes. It executes total += child_total: 2 + 7 = 9. Its loop is finished, so the parent returns 9, which becomes answer.
parent: nested_total([2, [3, 4]])
  total = 2; waits for a child result
  child: nested_total([3, 4])
    total = 0 → 3 → 7
    returns 7
  total = 2 + 7 = 9
  returns 9

The decisive step is total += child_total. Returning 7 does not automatically change the parent’s total. A returned value is a value the caller can use—not an instruction to update the caller’s variables.

Why does it stop?

A call only starts another call when it encounters a list. A list containing only integers starts no further calls: it finishes its loop and returns. An empty list also starts no calls; its loop runs zero times and it returns the initial 0. That is the stopping case, often called the base case, built into this loop rather than written as a separate if.

With a finite nesting structure and no cycles, following inner lists eventually reaches a list with no further inner lists. Each finished child then lets its waiting parent continue.

A. Recall and transfer

Use the same function with [2, [5, [1]], 3]. Write:

  1. What must a parent do with the number its child returns?
  2. What does the call for [1] return, and which call receives it?
  3. What does the call for [5, [1]] return?
  4. What is the final result? Show the outer total before and after the child returns, then after the last integer.
Check A: trace and reasoning

The parent must add the returned number to its own total. Calling the child alone is not enough.

The innermost call for [1] returns 1 to the call processing [5, [1]]. That call has already accumulated 5; adding the returned 1 makes 6, which it returns to the outer call.

The outer total follows 0 → 2 → 8 → 11: add 2, add the child’s returned 6, then add the last 3. The final result is 11.

If you got the number but cannot identify which call receives each return, redraw the three calls. Each return goes to the call that directly requested it, not straight to the outermost call.

B. Diagnose a lost answer

Suppose the list branch is changed to this, leaving the rest of the function unchanged:

if isinstance(item, list):
    nested_total(item)  # return value not used
else:
    total += item

For [2, [3, 4]], what does this version return? Does the child fail to run, or does its answer fail to reach the parent’s total? Write the repair.

Check B: the missing operation

It returns 2. The child still runs and returns 7, but the caller discards that returned value. The parent’s total stays at 2.

Restore the original two lines, or combine them as:

total += nested_total(item)

The right-hand call finishes first and supplies 7; then the parent adds it. The parent does not need to see every inner addition—only the child’s completed total.

4. Keep one rule, check one limit · 2 minutes

Each call owns a total. Each child returns one number. The parent adds that number, continues its loop, and finally returns its own total.

Before opening the answer, predict nested_total([2, []]). Explain why the empty list ends rather than requesting another call.

Check the empty-list boundary

The result is 2. The child for [] has no items, so its loop does nothing and it returns 0. The parent adds that 0 to 2. No special exception is needed.

Limits: this function is for integers and nested lists, not arbitrary Python objects. It does not detect a list that contains itself. Very deep nesting can exceed Python’s recursion limit even when the input is finite; this small teaching example is not a general-purpose input validator.
