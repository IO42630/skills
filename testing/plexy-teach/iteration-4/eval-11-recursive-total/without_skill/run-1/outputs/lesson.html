PYTHON · 10-MINUTE WORK-THROUGH

Nested lists, one total

You already know loops and return. Recursion adds one idea: a function can call itself to solve a smaller version of its own task.

By the end, you should be able to trace a nested sum, explain where each returned number goes, and write the function yourself. Use paper or think aloud. Predict before opening each answer.

0–1 MINUTE · THE IDEA

A sublist is another summing job

A flat list is familiar:

total = 0
for item in [2, 3, 4]:
    total += item
# total is 9

Now consider [2, [3, 4], 5]. At the outer level, the loop sees exactly three items: a number, a list, and a number. It does not automatically visit the numbers inside that list.

Instead of adding the list itself, ask the summing function to process [3, 4]. It returns 7, which the outer call can add just like any other number: 2 + 7 + 5 = 14.

The key: “Sum this sublist for me, then give me its subtotal.” The caller pauses during that job and resumes when it receives the result.
1–3 MINUTES · READ THE FUNCTION

The same code, a fresh local total

def nested_total(items):
    total = 0
    for item in items:
        if isinstance(item, list):
            total += nested_total(item)
        else:
            total += item
    return total
  • isinstance(item, list) asks whether this item is a list.
  • A number goes straight into this call’s total.
  • A list becomes the input to a new call of nested_total. That new call starts its own total = 0.
  • return total runs after the loop. The subtotal goes back to whichever call asked for it.

When you read total += nested_total(item), mentally split it into two actions: wait for a returned number; then add that number. The two calls do not share a total.

Predict: What does nested_total([]) return? Which lines run?
Reveal the empty-list answer

It returns 0. The call initializes total, skips the loop because there are no items, and reaches return total.

This is a stopping case with no explicit if items == [] needed. A list containing only numbers also finishes without making another recursive call.

For this lesson, inputs are finite lists containing only numbers and more lists, with no list containing itself. Each recursive call moves down to a child list; eventually it reaches numbers or an empty list, so the descent ends.

3–6 MINUTES · FOLLOW THE RETURNS

Down to the numbers, back up with subtotals

Trace nested_total([2, [3, [4], 1], 5]). We’ll name the calls A, B, and C to keep their local variables separate. These labels are just for the explanation, not different functions.

A: items = [2, [3, [4], 1], 5]
B: items = [3, [4], 1]
C: items = [4]

Think of each call as a work card holding its input, its running total, and its place in the loop. Pausing A does not erase A’s card.

Read one row at a time. Track which call owns each total.
StepWhat runs?Local totals and returns
1A starts and adds 2.A’s total: 0 → 2.
2A encounters [3, [4], 1] and calls B.A pauses at 2; B starts at 0.
3B adds 3.B’s total: 0 → 3. A still holds 2.
4B encounters [4] and calls C.B pauses at 3; C starts at 0.
5C adds 4, finishes its loop, and returns.C returns 4 to B, not directly to A.
6B resumes the waiting addition.B’s total: 3 + 4 = 7.
7B adds its next item, 1, then returns.B’s total: 7 + 1 = 8. B returns 8 to A.
8A resumes the waiting addition.A’s total: 2 + 8 = 10.
9A adds its next item, 5, then returns.A’s total: 10 + 5 = 15. Final result: 15.
Cover the table: Just before C returns, what are A’s and B’s totals? After C returns, which call resumes, and which item will that call process next?
Check your understanding of pausing

A has 2; B has 3. B resumes first, adds C’s returned 4 to get 7, and then processes its next item, 1. A stays paused until B finishes its whole list.

No double counting: B handles the numbers inside its list. A adds only B’s returned subtotal, once; A’s own loop never separately visits those inner numbers.
6–8 MINUTES · TRY WITHOUT THE TRACE

Predict, then explain

For nested_total([1, [2, [3]], 4]), write these three answers before opening the solution:

  1. What does the call on [3] return?
  2. What does the call on [2, [3]] return?
  3. What is the final result, and why does the outer 4 still get added?
Reveal the worked solution

[3] returns 3. Its caller on [2, [3]] adds that to 2 and returns 5. The outer call adds that subtotal to its existing 1, then resumes its loop at 4: 1 + 5 + 4 = 10.

If you got 6, you stopped the outer loop too soon. A child’s return ends only that child’s call, not all the waiting calls.

Empty sublist check: Predict nested_total([[], 6, [2, []]]). Does an empty child list end the outer call?

Reveal the empty-sublist solution

The result is 8: the outer call adds 0, then 6, then the subtotal 2 + 0. An empty child returns 0 to its caller; the caller then continues its own loop.

8–10 MINUTES · BUILD IT YOURSELF

Turn the explanation into code

Without looking at the original function, fill in the three blanks. Keep the indentation shown.

def nested_total(items):
    total = 0
    for item in items:
        if isinstance(item, list):
            total += ________
        else:
            total += ________
    return ________
Reveal the three expressions

In order: nested_total(item), item, total.

The recursive call receives the child list, not items. Calling again with the same outer list would repeat the same unfinished job instead of moving down.

Spot the bug: Someone puts return total inside the for loop, immediately after the if/else. What would their function return for [2, [3, 4], 5]?

Reveal the bug and fix

It returns 2 after the first iteration. The list and the final 5 are never processed. Keep return total outside the loop so all items contribute. That also lets the empty-list case reach the return.

Exit check: Finish this sentence in your own words: “When a call sees a sublist, it pauses with its own total, asks ________, then uses the returned number to ________.”
Compare your explanation

“…asks a new call of the same function to sum that sublist, then uses the returned number to increase its own total and continue its loop.” If that feels uncertain, revisit steps 4–8 of the trace and point to the caller receiving each return.

Takeaway: The loop handles siblings. Recursion handles a child list. Each call owns its subtotal; returning passes that subtotal one level back up.
