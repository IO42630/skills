Nested lists, one total

Recursion is not a new kind of loop. It is a function call that asks the same function to solve a smaller piece, then uses the number it returns.

You already know loops and returns. By the end, you will trace a nested-list total, explain what a waiting call remembers, and fill in the recursive line yourself.

Minute 0–1 · Start from what you know

1. A list can contain another job

For a flat list such as [2, 3, 4, 5], you can start a subtotal at zero, loop through the numbers, and add each one. Now consider:

[2, [3, [4]], 5]

The outer loop sees three items: the number 2, the list [3, [4]], and the number 5. You cannot add that middle list directly to a number.

The rule: If the item is a number, add it. If it is a list, ask the same function for that list’s total, and add the returned number.

This is a smaller version of the same job: “total this list” becomes “total this inner list.” You do not need to know its nesting depth in advance.

Say it before moving on: If the inner list’s total is 7, what calculation does the outer list need?
Reveal the calculation

2 + 7 + 5 = 14. The parent call needs just one number from the child call, not all of the child’s intermediate work.

Minutes 1–3 · Read the function

2. One call promises one number

Function contract: Give total a list of numbers and/or nested lists. It returns the sum of every number inside it, at any depth.

def total(items):
    subtotal = 0
    for item in items:
        if isinstance(item, list):
            subtotal += total(item)
        else:
            subtotal += item
    return subtotal

print(total([2, [3, [4]], 5]))  # 14
  • isinstance(item, list) asks whether the current item is a list.
  • total(item) makes a new call, with that inner list as its input. This is the recursive step.
  • subtotal += total(item) means: first get the child’s return value, then add it to this call’s subtotal.
  • return subtotal is outside the loop. A call finishes only after handling all its items.
Each call has its own variables. The child starts its own subtotal = 0; that does not reset the parent’s subtotal. The parent waits at the function call, then resumes with the returned value.

Where does it stop?

A number is handled directly: no more calls are needed for it. A list containing only numbers makes no recursive calls. An empty list runs the loop zero times and returns 0. These are the stopping cases; an extra explicit base-case if is not needed here.

Scope: finite lists containing ordinary integers or floats and other lists. Strings, dictionaries, booleans, and lists that contain themselves are outside this lesson’s input contract. Descending through a finite, non-circular nesting eventually reaches numbers or empty lists. Extremely deep nesting can hit Python’s recursion limit.

Minutes 3–6 · Trace the worked example

3. Down through calls, back through returns

Trace total([2, [3, [4]], 5]). We will label its calls A, B, and C to keep their separate work visible. These are labels for three invocations of the same function, not three different functions.

A: total([2, [3, [4]], 5])
                  │
                  └── B: total([3, [4]])
                                     │
                                     └── C: total([4])
Read top to bottom. A waiting call keeps its place in its loop.

1A starts and adds its first item, 2.A: 0 → 2.

5B resumes at its paused addition: subtotal += total(item).The return value fills in the right side: 3 + 4 = 7. A is still at 2.
6B’s loop ends. B returns 7 to A.A resumes its paused addition: 2 + 7 = 9.

8A’s loop ends and returns 14.The original caller gets 14; print displays it.

Freeze the picture just before C returns

A · waitingsubtotal = 2

Needs B’s result. The final 5 has not been visited.

B · waitingsubtotal = 3

Needs C’s result to finish its addition.

C · runningsubtotal = 4

Returns 4 to B next.

These separate workspaces are called call frames. Python keeps them on a call stack: the most recently started call finishes first. A does not continue to 5 while B is still running.

Pause: When C returns 4, which subtotal changes first: A’s or B’s? Why is the final answer not 4?
Reveal the return path

B’s subtotal changes first, from 3 to 7, because B directly called C. C’s return ends C’s call only, not all calls. B must return its own 7; then A adds that and its remaining 5, and finally returns 14.

If you pictured one shared subtotal, revisit the three boxes. A’s 2, B’s 3, and C’s 4 coexist in different frames.

Minutes 6–8 · Try the mechanism yourself

4. Predict before revealing

total([1, [2, 3], [], 4])
Write four answers:
  1. What subtotal does the outer call hold while total([2, 3]) runs?
  2. What does that child return, and what is the outer subtotal immediately afterward?
  3. What does total([]) return? Does it erase the outer subtotal?
  4. What is the final return value?
Check your predictions and reasoning
  1. The outer call waits with 1. It has not yet handled [] or 4.
  2. The child starts at zero and adds 2 + 3, returning 5. The outer subtotal becomes 1 + 5 = 6.
  3. The empty-list call returns 0: its loop has no items. The outer call adds that zero and remains at 6. The child’s initialization does not erase the parent’s local variable.
  4. The outer call adds 4 and returns 10.

If you got the total but not the middle steps: focus on the paused addition, not just adding all visible numbers. Trace the child’s returned number landing in the parent’s subtotal.

Minutes 8–9 · Turn the idea into code

5. Supply the missing line

Do not scroll back to the full function yet. What should replace the blank?

def total(items):

        if isinstance(item, list):
            ______________________
        else:

Choose and explain: total(item), subtotal = total(item), or subtotal += total(item)?
Reveal the line and the two traps 
subtotal += total(item)
  • total(item) alone computes a number but throws away its return value. The child’s subtotal does not automatically update the parent’s.
  • subtotal = total(item) replaces the parent’s accumulated total, losing numbers already handled.
  • subtotal += total(item) adds the child’s result to what the parent already has.

Also keep return subtotal outside the loop. Moving it inside would end this call after its first item; on [1, [2, 3], [], 4], that would return just 1.

Minutes 9–10 · Explain it without the example

6. A fresh list, the same rule

total([[], [6, [-2, 1]], 3])
Final check: Predict the result. Then explain what total([-2, 1]) returns, what its parent does with that value, and why recursion eventually stops.
Check the answer

The first child, total([]), returns 0. The deepest child, total([-2, 1]), returns -1. Its parent adds that to 6 and returns 5. The outer call returns 0 + 5 + 3 = 8.

Negative numbers need no special recursion rule; they are still numbers to add. The calls stop descending when they reach numbers or empty lists. Every call then finishes its own loop and returns to whoever called it.

Your one-sentence explanation: “Each call totals its own list; for an inner list it pauses, gets that list’s total from another call, adds the returned number, and continues its loop.”

Ready to move on? You should be able to explain all three ideas without looking:

  • Every call has a separate subtotal.
  • A return goes back to the immediate caller, which resumes its paused addition.
  • Numbers are handled directly, and an empty list contributes zero.

If one still feels slippery, revisit the frozen call frames in section 3 and point to the exact box that receives each return.
