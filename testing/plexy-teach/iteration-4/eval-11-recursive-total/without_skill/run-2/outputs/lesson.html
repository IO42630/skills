One list at a time

A recursive function does not solve the whole nested list at once. It asks another call to total one inner list, then uses the returned number.

You already know loops and function returns. We will use those two ideas to explain why calling a function from inside itself works.

Your target: trace nested_total([2, [3, [4]], 5]), explain what each call returns, and complete the recursive line yourself.

0–1 MINUTE · START WITH A FAMILIAR LOOP

What changes when an item is a list?

def flat_total(items):
    total = 0
    for item in items:
        total += item
    return total

For [2, 3, 4, 5], this loop returns 14. But for [2, [3, [4]], 5], the second item is a list, not a number. Python cannot add that list to total.

Predict: If every number inside the brackets counts exactly once, what should the nested list's total be?
Check your prediction

2 + 3 + 4 + 5 = 14. The brackets group numbers; they do not add extra values. We need a way to turn each inner list into its subtotal.

1–3 MINUTES · THE SAME JOB, ON A SMALLER LIST

Keep the loop. Delegate the inner list.

Input agreement: the input is a list containing numbers and/or other lists of the same kind. Empty lists and negative numbers are allowed. Strings, tuples, and other objects are outside this lesson's input agreement.

def nested_total(items):
    total = 0
    for item in items:
        if isinstance(item, list):
            total += nested_total(item)
        else:
            total += item
    return total

print(nested_total([2, [3, [4]], 5]))
# Expected output: 14
  • isinstance(item, list) asks whether this item is a list.
  • Number? Add it directly, just like your familiar loop.
  • List? Call nested_total(item) to get a number back, then add that number.
  • Loop finished? Return this call's accumulated total.
Recursion means a function calls itself. It is the same function code, but a new call with its own items, its own total, and its own place in the loop.

Think of total += nested_total(item) as three actions:

subtotal = nested_total(item)  # wait for this call to return
total = total + subtotal      # add its returned number
# then continue this call's loop

The inner call starting at total = 0 does not reset the waiting outer call's total.

Why does the calling stop?

A number takes the else branch: no new call. An empty list has no loop iterations and returns 0. These are the stopping cases; they do not need a separate early-return line here.

For a finite nested list without circular references, each recursive call goes into an inner list. Eventually there are only numbers or empty lists, so the calls finish. A list containing itself is not covered, and extremely deep nesting can hit Python's recursion limit.

3–6 MINUTES · PAUSE, RETURN, RESUME

Follow three calls, not one giant loop

We will name the calls A, B, and C. These are labels for this explanation, not different functions.

A: nested_total([2, [3, [4]], 5])
                    ↓ asks for the inner list
B:     nested_total([3, [4]])
                        ↓ asks for the inner list
C:         nested_total([4])
Pause here: A has added 2 and is about to call B. Does A add 5 before B returns? What value must B return?
Check the pause-and-return prediction

No: A waits at the call to B. B must return 7, the total of [3, [4]]. Only then can A add 7 and move to its next item, 5.

If you expected A to continue immediately, focus on an ordinary function call: its return value must be available before the addition can finish. A recursive call follows that same rule.

The actual order of work
StepActive call and actionWaiting calls
1A starts at 0; adds 2 → A's total is 2.None
2A reaches [3, [4]] and calls B. B starts at 0, adds 3 → 3.A: total 2, waiting for B
3B reaches [4] and calls C. C starts at 0, adds 4 → 4.A: 2; B: 3, waiting for C
4C's loop ends. C returns 4 to B.A: 2
5B resumes: 3 + 4 = 7. B's loop ends; B returns 7 to A.A: 2
6A resumes: 2 + 7 = 9. A adds its next item, 5 → 14, then returns 14.None
Going down: ask an inner list for its total.
Coming back: receive a number, add it, and continue the waiting loop.

Only C directly adds the number 4. B receives it as a subtotal, and A receives B's subtotal. They do not visit and count that same leaf again.

6–9 MINUTES · YOUR TURN

Build the return values from the inside out

1. Trace this input: [-1, [2, [], [3]], 4].

Write four results: the return from [], from [3], from [2, [], [3]], and finally from the whole list. For each, use only its own direct numbers and returned subtotals.

Check the four results and the order
  • [] returns 0: its loop never runs.
  • [3] returns 3.
  • [2, [], [3]] returns 2 + 0 + 3 = 5.
  • The outer call returns -1 + 5 + 4 = 8.

The outer call waits with total -1. The middle call adds 2, calls the empty list, adds its returned 0, calls [3], then adds its returned 3. It returns 5; the outer call can now finish.

If you left a blank for [], remember that return total still runs even when the loop does not. If you got 9, check that the negative number was included.

2. Fill the blank without looking above. Why should this call receive item, not items?

if isinstance(item, list):
    total += __________________
else:
    total += item
Check the missing expression

nested_total(item). We want the subtotal of this one inner list. Passing items would restart work on the same whole list; whenever it reached this inner list, it would make the same call again, without progressing toward a stopping case.

3. Spot the early return: If return total were indented inside the for loop, what would the function return for [2, [3, [4]], 5]?
Check the bug and its fix

It would return 2 immediately after the first item, skipping the rest. Keep return total outside the loop so every item contributes. That placement also lets an empty list return 0 rather than implicitly returning None.

Compare with a complete explanation

“One call returns the sum of all numbers in the list it received, including deeper lists. It adds direct numbers itself and delegates inner lists to new calls. The caller waits with its own total unchanged, then adds the returned subtotal and continues. Numbers do not trigger calls; empty lists return zero. In finite, non-circular inputs, that lets all calls finish.”

[] returns 0; [6] returns 6. The outer call computes 0 + 6 - 2 = 4.
