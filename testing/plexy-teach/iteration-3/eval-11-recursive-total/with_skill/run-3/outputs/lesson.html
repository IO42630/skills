A nested list returns its subtotal

Your goal: trace a recursive total and explain exactly how the numbers inside a child list contribute to the outer list’s answer.

You already know loops and function returns. We will add one idea: a function can call itself on a smaller piece of its input.

1. Turn a child list into one number · 2 minutes

Consider [2, [3, 4]]. The outer loop sees two items: the number 2 and the list [3, 4]. It does not directly see 3 and 4 as its own items.

To add that second item, ask the same function to total [3, 4]. That call returns 7. Now the outer call can add two numbers: 2 + 7.

Recursion here means: “I can total this list if another call totals each child list for me.” The child’s returned number is useful only if the parent adds it.

Here is the complete function for lists containing numbers and other lists:

def total(items):
    result = 0
    for item in items:
        if isinstance(item, list):
            result += total(item)
        else:
            result += item
    return result

isinstance(item, list) asks whether this item is a list. If it is, total(item) supplies a number to add. Otherwise, the item is already a number. Notice that return result is after the loop: every item must contribute before this call finishes.

2. Follow the call down, then the answer back · 3 minutes

Each call has its own items and result. “Parent” means the call waiting for another call; “child” means that other call. These are not different functions—just separate executions of total.

  1. Parent starts: total([2, [3, 4]]) sets its result to 0.
  2. Its first item is 2, so the parent’s result becomes 2.
  3. Its next item is [3, 4]. To finish result += total(item), it needs the child’s answer. The parent waits, still holding 2.
  4. Child starts: total([3, 4]) creates a fresh result of 0, adds 3, then adds 4. Its result is now 7.
  5. The child reaches return result and returns 7 to the waiting parent.
  6. Parent resumes: its pending addition now uses that answer: 2 + 7 = 9. Its loop ends, and it returns 9.
total([2, [3, 4]])     parent result: 0 → 2
    total([3, 4])     child result:  0 → 3 → 7
    returns 7
parent adds 7          parent result: 2 → 9
returns 9

The child does not change the parent’s result directly. Its result becomes a return value; the parent’s += adds that value. If the parent has more items, its loop continues with the next one.

Why doesn’t it call itself forever?

A list containing only numbers makes no further calls. An empty list, [], runs the loop zero times and returns its starting result, 0. These are stopping cases, often called base cases. No separate if not items is needed in this version.

For a finite nested structure without a list containing itself, repeatedly entering child lists eventually reaches a stopping case. Each answer then returns to the call that asked for it.

3. Make the return journey yourself · 4 minutes

Cover the function above. Write your answers before opening each explanation. A final number alone is not enough—track who returns it and who adds it.

A. Retrieve the rule

What does a call do with a number? What does it do with a list? What does an empty list return? When is a call ready to return its own result?

Reveal the rule and check your explanation

Add a number directly. For a list, call total on that list and add the returned subtotal. An empty list returns 0 because there were no additions. Return this call’s result only after its loop has processed every item.

If you wrote “call the function on the child,” add the missing step: use the child’s returned value in the parent’s addition.

B. Apply it to a changed input

total([1, [2, []], 3])

Predict the final total. Then write the return values in the order the calls finish, and the outer call’s running result. Explain why the outer 3 is not lost when the child returns.

Reveal the trace and reasoning
  1. The outer call adds 1, then waits for total([2, []]).
  2. That child adds 2, then waits for total([]).
  3. The empty-list call returns 0. The child adds it: 2 + 0 = 2, then returns 2.
  4. The outer call adds that 2: 1 + 2 = 3. Its loop then handles its last item, 3, making 6. It returns 6.

The return values, from first finished call to last, are 0 → 2 → 6. The outer running result is 0 → 1 → 3 → 6. A child’s return ends only the child call; it does not end the parent’s loop.

If you got 3, check whether you stopped the parent when the child finished. If you counted the child’s 2 twice, remember that the outer loop adds its returned subtotal, not its internal numbers again.

C. Diagnose a tempting mistake

Suppose the list branch changes to this, with all other lines unchanged:

if isinstance(item, list):
    total(item)

What would total([2, [3, 4]]) return now? Does the child run? Which operation must be restored, and why?

Reveal the diagnosis

It returns 2. The child still runs and returns 7, but the parent discards that value. Running a function is not the same as using its answer.

Restore result += total(item). The parent needs an explicit addition to carry the child’s subtotal into its own result. Making the child run again would not fix the missing addition.

4. Keep this rule · 1 minute

Numbers add directly. Child lists return subtotals. The parent adds each subtotal, continues its loop, then returns its own total.

This function assumes every item is a number or a list, with no self-containing lists. It does not modify the lists. Very deep nesting can exceed Python’s recursion limit; handling arbitrary data or extreme depth is outside this lesson.
