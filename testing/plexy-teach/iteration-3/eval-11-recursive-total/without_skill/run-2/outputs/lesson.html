Where does the nested total come from?

A recursive function does not add everything at once. It asks another call to total one nested list, waits for that answer, and then continues its own loop.

Your goal: trace a nested total and explain how a returned number gets back to the caller.

Work from top to bottom. Predict before opening an answer. No Python installation is needed; the code is provided if you want to try it later.

1. Start with a loop 2. Add one rule 3. Follow the calls 4. Predict 5. Explain and repair
0–1 minute

1. Start with the loop you know

def flat_total(items):
    subtotal = 0
    for item in items:
        subtotal += item
    return subtotal

flat_total([2, 3, 4])  # returns 9

Each number increases subtotal. But in [2, [3, 4], 1], the second item is a list, not a number. Adding that list to a number would raise a TypeError.

We need a number in its place: the total of [3, 4]. That is the same kind of job, just for one part of the original input.

The recursive idea: “I know how to total a list. If one item is another list, ask the same function to total that item.”
1–3 minutes

2. Add one rule: turn a list into its total

def total(items):
    subtotal = 0
    for item in items:
        if isinstance(item, list):
            subtotal += total(item)
        else:
            subtotal += item
    return subtotal

isinstance(item, list) asks whether the current item is a list.

  • Number: add it directly. No new call is needed.
  • List: call total(item). Add the number it returns.
  • Loop finished: return this call’s subtotal.

For understanding, read the recursive line as these two steps:

child_total = total(item)  # wait here for a number
subtotal += child_total   # then update this call's subtotal
Same function, different call. Each call has its own items, item, and subtotal. Starting the child at zero does not reset the parent. The parent keeps its place in the loop while it waits.

What makes it stop?

A flat list adds only numbers and then returns. An empty list has no loop iterations, so it returns 0. These are the stopping cases: no further recursive call is needed. They do not require a separate if in this version.

Scope: a finite list containing only numbers and other such lists. Each call descends one level into a child list; with finite nesting and no list containing itself, that descent must end. Strings, other container types, and cyclic lists are outside this lesson.

3. Follow the call down—and the answer back up

Pause: Why does A still add 1 after B returns?

Reveal the explanation

B’s return ends only B’s call. A resumes at its waiting addition, adds 7, and continues its own loop. The final return in A is outside the loop, so A processes all its items first.

Downward: calls ask for totals of child lists.
Upward: completed calls return numbers to their immediate callers.
No list is added to a number, and no shared “master subtotal” is needed.

6–8 minutes

4. Predict before revealing

For each input, work out the child’s returned number first, then finish the parent’s loop. Write or say your answer before opening the explanation.

A. One child

total([4, [1, 2], 3])

Check A

The child total([1, 2]) returns 3. The outer call computes 4 + 3 + 3 and returns 10.

If you got 7, you may have stopped the outer loop after the child. It must still add the final 3.

B. An empty child and another level

total([-2, [5, [], [1]], 3])

Check B

total([]) returns 0; total([1]) returns 1. Their parent returns 5 + 0 + 1 = 6. The outer call returns -2 + 6 + 3 = 7.

The empty child does not end its parent’s loop. It simply supplies a zero, and the parent moves on.

8–10 minutes

5. Repair the missing connection

Suppose someone changes just the list branch to this:

if isinstance(item, list):
    total(item)
else:
    subtotal += item

The rest of the function stays the same. For [2, [3, 4], 1], what would this broken version return? What single line fixes it?

Reveal the diagnosis and repair

It returns 3. The child computes and returns 7, but the outer call throws that result away. Only the outer numbers 2 and 1 increase its subtotal.

subtotal += total(item)

Calling the function is not enough. The caller must use its return value.

Compare with a model explanation

“When my loop sees a nested list, it calls the same function on that list; while that happens, my subtotal stays saved in my own call; when the child returns, I add its number and continue my loop.”

Takeaway: Each call totals its own list. Numbers are added directly; nested lists become numbers through recursive calls. A return passes one completed subtotal back up one level.
