Python · 10-minute lesson · loops → recursion

A recursive total, one return at a time

A nested list is still a list. Its items just sometimes need their own little calculation.

By the end, you will be able to trace a nested total, explain what happens while a function waits for another call, and write the recursive step yourself.

The job · The function · Follow the returns · Predict · Build it

0–1 minute · Start with what you know

Add numbers, not brackets

For [2, 3, 5], you already know the loop: start at zero, then add each number. Now imagine this:

numbers = [2, [3, [4], 1], 5]

First prediction: What should the total be? Ignore the brackets and add the numbers mentally.

Check the target total

2 + 3 + 4 + 1 + 5 = 15. We want to count every number exactly once, regardless of depth.

The outer loop sees only three items: 2, a list, and 5. You cannot add that list directly to a number. But you can ask a function to turn the list into a subtotal.

The recursive idea: when an item is another list, use this same function to total that smaller list. Add the number it returns.

1–3 minutes · Read the loop you already understand

One function, many separate calls

def nested_total(items):
    total = 0
    for item in items:
        if isinstance(item, list):
            subtotal = nested_total(item)
            total += subtotal
        else:
            total += item
    return total

numbers = [2, [3, [4], 1], 5]
print(nested_total(numbers))  # 15

isinstance(item, list) asks whether this item is a list. A number takes the ordinary addition branch. A list takes the recursive branch.

  1. Start: this call gets its own items, total, and loop position.
  2. Delegate: nested_total(item) starts a new call for that sublist. The current call waits.
  3. Resume: the child returns one number. The waiting call stores it in subtotal, adds it, and continues its loop.
  4. Finish: return the total after the loop, not during it.

Nothing gets reset in the waiting call. Each call has a separate local total. A child's total = 0 does not erase its parent's total.

What makes it stop?

Our inputs are finite lists containing only numbers and more such lists, with no list containing itself. Each recursive call goes down into a contained sublist. Eventually a call sees only numbers, or an empty list, so it makes no further calls and returns.

For [], the loop runs zero times and returns 0. There is no separate base-case if here: the no-more-sublists case stops recursion naturally. “Smaller” means less nesting left to descend through, not necessarily fewer items.

3–6 minutes · Follow the pauses and returns

The parent waits; the child does its own loop

We'll label the calls A, B, and C. These are labels for separate executions, not different functions.

A: nested_total([2, [3, [4], 1], 5]) → 15
    B: nested_total([3, [4], 1])     → 8
        C: nested_total([4])        → 4

Calls start inward: A → B → C. Then the returned subtotals travel outward: C → B → A.

The execution order, with each call's local total
StepActive call and actionWaiting calls
1A starts at 0; adds 2 → A total 2.None.
2A reaches [3, [4], 1] and calls B.A waits with total 2.
3B starts at 0; adds 3 → B total 3.A still has 2.
4B reaches [4] and calls C.A has 2; B has 3.
5C starts at 0; adds 4; returns 4.A and B have not changed.
6B receives 4; adds it → 7. B then adds its next item, 1 → 8, and returns 8.A still has 2.
7A receives 8; adds it → 10. A then adds its next item, 5 → 15, and returns 15.None. The original call is done.

Pause and say it aloud: Why does C returning 4 not make the entire calculation end at 4?

Check your explanation

return ends only the call executing it. C returns to B at B's subtotal = nested_total(item) line. B still has its own loop to finish; then B returns to A. Only A's final return goes back to the original caller.

Replace a call with its returned value: in A, nested_total([3, [4], 1]) eventually supplies 8. A therefore computes 2 + 8 + 5. You do not need to flatten or modify the list.

6–8 minutes · Predict before revealing

Try a fresh input

For nested_total([1, [2, [3]], []]), write three things:

  1. What does the call on [3] return?
  2. What does the call on [2, [3]] return?
  3. What does the outer call return after processing []?

This is a scratchpad, not a Python runner. The page does not submit or save your notes.

Reveal the trace

[3] returns 3. The middle call adds 2 + 3 and returns 5. The outer call adds 1 + 5, then calls the function on []. That call returns 0, so the final result is 6.

If you got 0 overall, remember that the empty list's return is added to the parent's existing total; it does not replace it.

One more check: predict nested_total([[[-2]], 5]). Do extra brackets change the value of a number?

Reveal the answer

The result is 3. Each inner call passes the subtotal -2 outward; the outer call adds 5. Nesting does not multiply a number or count it again.

8–10 minutes · Reconstruct the idea

Fill the gap, then check the return

On paper or in your notes, replace ??? with one expression. Explain why it produces a number rather than a list.

def nested_total(items):
    total = 0
    for item in items:
        if isinstance(item, list):
            total += ???
        else:
            total += item
    return total
Reveal the missing expression

nested_total(item). It totals this sublist and returns a number to add. This is the earlier two-line recursive branch written in one line.

nested_total(items) would call the function on the whole current list again. When that list contains a sublist, it repeats the same problem without getting closer to stopping.

Spot the bug: Suppose return total moves inside the for loop, after the if/else. What would happen to the original input [2, [3, [4], 1], 5]?

Reveal the bug and fix

The outer call would return 2 after its first item, never reaching the sublist or the final 5. For an empty list, that misplaced return would never execute, so Python would return None.

Keep return total outside the loop, aligned with for. Each call must finish all of its own items.

Your exit check

Without looking back, explain: “When a loop item is a list, I _____ . The parent keeps _____ while it waits. The child returns _____, and the parent _____ .”

Compare with a complete explanation

“I call the same function on that sublist. The parent keeps its local total and loop position while it waits. The child returns a subtotal, and the parent adds it and continues with the next item.”

If the waiting part still feels unclear, revisit steps 4–7 in the table and track A's 2 separately from B's 3.

Keep this mental model: each call totals one list. Numbers are added directly; sublists are replaced by their returned subtotals. Separate local totals, one return at a time.

Scope: finite, non-self-referential Python lists of numbers and lists. Strings, other containers, and extremely deep nesting are outside this exercise; Python has a recursion-depth limit.
