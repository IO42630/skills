A child returns a number.
The parent adds it.

You already know loops and function returns. Here you will trace a recursive total through a nested list and explain exactly how an inner list's answer becomes part of the outer answer.

No Python execution is needed. Use paper or say each subtotal aloud. Try the exercises before opening their answers.

1. A list inside a list is one smaller job

For [2, [3, 4]], the total we want is 2 + 3 + 4 = 9. The outer loop sees only two items: the number 2 and the list [3, 4]. It cannot add that list as if it were a number.

Instead, it asks the same function to total [3, 4]. That call returns 7. Now the outer call can add 2 + 7.

Recursion means a function calls itself on a smaller part of the input. In this example, the smaller call turns an inner list into a number that its caller can use.

We'll call the waiting caller the parent and the call it makes the child. These are roles, not different functions.

def total(items):
    subtotal = 0
    for item in items:
        if isinstance(item, list):
            subtotal += total(item)
        else:
            subtotal += item
    return subtotal

isinstance(item, list) asks whether this item is a list. If it is, compute its total first; otherwise, add the number directly. return subtotal is after the loop, so every item contributes before the answer leaves the call.

Input assumption: finite nested Python lists, with numbers at the leaves and no list containing itself, directly or indirectly. We are teaching the return flow, not input validation.

2. Follow the pause, then the return

Trace total([2, [3, 4]]). Every call has its own items and subtotal. Starting a child does not reset the parent's subtotal.

  1. Parent starts. Its items is [2, [3, 4]]; its subtotal starts at 0. The first item is 2, so the parent's subtotal becomes 2.
  2. Parent reaches the inner list. To do subtotal += total(item), it must get the right-hand number first. It calls total([3, 4]) and waits. Its subtotal is still 2.
  3. Child does its own loop. Its subtotal starts at 0, becomes 3, then 7. Its loop ends, so it returns 7 to the waiting parent.
  4. Parent resumes the unfinished addition. In that call, subtotal += total(item) now has the effect of subtotal += 7. The parent's subtotal becomes 2 + 7 = 9.
  5. Parent finishes. There are no more outer items. It returns 9 to whoever originally called it.
Parent: 0 → 2 ── waits ─────────→ 9 → return 9
Child:           0 → 3 → 7 → return 7
                              │
                     parent adds this 7

The child returns only its own subtotal, 7, not the whole answer, 9. It does not know about the parent's 2. The parent's addition is the bridge between those two answers.

3. Where does it stop?

A call only makes another call when it finds a list. The child working on [3, 4] finds only numbers, so it can finish without calling itself again. This is the stopping case for this trace.

An empty list also needs no smaller call: total([]) starts at 0, runs the loop zero times, and returns 0. There is no separate if not items needed in this version.

For a finite, non-circular nested list, following inner lists eventually reaches a list with no inner lists. Calls then return outward, one caller at a time. A list that contains itself would break this argument. Extremely deep nesting can also reach Python's recursion limit; this tiny teaching function is not a solution for arbitrary depth.

A · Retrieve the decisive step

In total([2, [3, 4]]), just before the child returns, what are the parent's and child's subtotals? What operation happens next in the parent?

Reveal the reasoning for A

The parent still has 2; the child has 7. The child returns 7, and the parent completes its pending addition: 2 + 7 = 9. If you thought the parent also had 7, you treated two local subtotals as one shared variable.

B · Trace one more level

Use the same function on [1, [2, [3]], 4]. Write the return value of the call on [3], then the call on [2, [3]], then the outer call. Explain what the outer loop does after its child returns.

Reveal the reasoning for B
  1. The deepest call, on [3], adds 3 to its own 0 and returns 3.
  2. The call on [2, [3]] was waiting with subtotal 2. It adds the returned 3 and returns 5.
  3. The outer call was waiting with subtotal 1. It adds 5, reaching 6. Then its loop continues to 4, reaching 10, which it returns.

Returning from a child does not end the parent's function. It supplies a value at the call site; the parent continues its own work. If you got 6, you stopped before the outer loop processed its last item.

C · Diagnose a lost answer

Suppose the list branch contains only total(item) instead of subtotal += total(item). All other lines stay unchanged. For [2, [3, 4]], what does the outer call return, and why?

Reveal the reasoning for C

It returns 2. The child still computes and returns 7, but the parent does nothing with that returned value. Calling the function is not enough: subtotal += total(item) is what incorporates the child's answer into the parent's subtotal.

Keep this rule

Each call owns its subtotal. Add numbers directly. For an inner list, wait for its total, add that returned number, and continue your loop. Return your subtotal only when your own loop is done.

Quick boundary check: total([1, [], 4]) is 5: the empty child returns 0, so nothing is lost and nothing extra is added. This reasoning assumes the finite, non-circular numeric lists described above.
