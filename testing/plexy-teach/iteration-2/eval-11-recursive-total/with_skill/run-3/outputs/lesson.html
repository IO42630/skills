10-minute lesson · Python loops and returns are enough

A recursive call gives back a number. Its caller must use it.

Your goal: trace a total through a nested list and explain exactly how an inner list’s result becomes part of the outer total.

We’ll use finite lists containing only numbers or more lists, with no list containing itself, directly or indirectly. No tree framework or other machinery is needed.

1. Keep the loop; delegate one item · 1 minute

For [2, 3, 4], a loop can add each item. For [2, [3, 4]], one item is a list, not a number. We need its total before we can add it.

The same function already knows how to total a list, so it can call itself on [3, 4]. That is recursion: a function using another call to itself to do part of its work.

Each call totals its own list. A child call returns one number; the parent call adds that number to its own running total.

“Parent” means the call doing the asking. “Child” means the call it starts. These are two executions of the same function, not two different functions.

2. Follow the value back · 4 minutes

This is complete Python for the restricted inputs above. Read the recursive line as: get this inner list’s total, then add it here.

def nested_total(items):
    total = 0
    for item in items:
        if isinstance(item, list):
            total += nested_total(item)
        else:
            total += item
    return total

isinstance(item, list) checks whether this item is a list. A number is added directly; a list is totaled by a new call. return total is after the loop, so the call processes all its items before returning.

Trace nested_total([2, [3, 4]])

  1. The parent starts with total = 0. Its first item is 2, so its total becomes 2.
  2. The next item is [3, 4]. At total += nested_total(item), the parent must get the right-hand value first. It waits with its own total still 2.
  3. The child starts a separate total = 0. Its loop adds 3, then 4, making 7. This does not reset or change the parent’s total.
  4. The child executes return total. It hands 7 back to the waiting parent. At that moment, the parent’s pending line works like total += 7, so its total becomes 2 + 7 = 9.
  5. The parent’s loop is finished. The parent now returns 9 to whoever called it.
Parent: [2, [3, 4]]   total: 0 → 2 → waits → 9
Child:      [3, 4]    total: 0 → 3 → 7
                                    │
                         returns 7 to parent

The parent resumes at the call site, not at the top of the function. Each new call has its own local items, item, and total. The returned number connects the calls.

Why does it stop?

A call recurses only for list items, going into a contained list each time. Eventually it reaches numbers or empty lists. Numbers need no new call; an empty list runs zero loop iterations and returns its starting total, 0. These are the stopping cases. Their results let the waiting calls finish in turn.

An empty list contributes zero; it does not cancel numbers already added. Termination here depends on finite nesting without cycles. Python also limits call depth, so this simple function is not a solution for arbitrarily deep nesting.

3. Make the value travel yourself · 4 minutes

Cover the worked trace. Write your answers on paper before opening each explanation. The reveals work without JavaScript.

A. Retrieve the mechanism

A parent has total 2 when its child returns 7. Explain why the child’s total = 0 did not erase the 2, and what makes the parent’s total become 9.

Compare your reasoning

The child’s total belongs to a separate call. The parent keeps its own 2 while waiting. The child returns 7; the parent’s += adds it to 2. Returning alone does not update the parent’s total.

B. Transfer to one more layer

Trace nested_total([1, [2, [3]], 4]). Write the return values for [3], [2, [3]], and the outer list, in that order. Beside each parent, show the addition that uses its child’s return. Don’t just add the visible numbers in your head.

Compare your trace
  1. [3] adds 3 to its own zero and returns 3.
  2. [2, [3]] already has 2 when the child returns. It performs 2 + 3 = 5 and returns 5.
  3. The outer call already has 1. It adds the returned 5, making 6, then continues its loop and adds 4. It returns 10.

If you got 6, you stopped the outer call too soon. A child’s return ends the child, not the parent’s loop. If you got 10 by counting numbers, check that your trace also shows where 3 and 5 are returned and added.

C. Diagnose a missing total

Suppose the list branch changes to this:

if isinstance(item, list):
    nested_total(item)  # no addition here

Everything else stays the same. What would the parent return for [2, [3, 4]]? Identify the lost value and repair the line.

Compare your diagnosis

The parent returns 2. The child still computes and returns 7, but the parent ignores that result. Repair it with total += nested_total(item). Calling the child does the inner work; using its return combines that work with the parent’s total.

4. Keep this rule · 1 minute

Numbers add directly. Lists return a subtotal. The caller adds that subtotal and keeps looping. Each call owns its running total; return values carry results back outward.

Before leaving, trace [2, []] aloud: the child returns zero, the parent adds zero to two, and the parent returns two. This is why an empty inner list needs no special exception.
