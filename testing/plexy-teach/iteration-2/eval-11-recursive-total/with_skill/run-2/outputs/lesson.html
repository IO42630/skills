How a recursive total comes back

Your goal: trace a nested-list total and explain exactly how a child call's returned number becomes part of its parent's total.

You already know loops and function returns. The new piece is keeping track of several calls to the same function, each with its own unfinished work.

1. A nested list becomes one number · 1 minute

For [2, [3, 4]], a loop sees two items: the number 2 and the list [3, 4]. You cannot add that list directly to a number. First, get its total: 7. Then the outer calculation is 2 + 7 = 9.

Recursion: the function asks itself to solve the same kind of problem for a smaller part. The child call returns a number; the parent adds that number and continues its loop.

“Parent” and “child” just describe which call requested which other call. They are not different functions.

2. Follow the number back up · 4 minutes

This complete Python example assumes each item is an integer or another list, with finite nesting and no list containing itself, directly or indirectly. It sums the numbers; it does not change the lists.

def nested_total(items):
    subtotal = 0
    for item in items:
        if isinstance(item, list):
            subtotal += nested_total(item)
        else:
            subtotal += item
    return subtotal

print(nested_total([2, [3, 4]]))  # 9

isinstance(item, list) asks whether the current item is a list. For a number, add it directly. For a list, call nested_total on that list and add the returned number.

Each call starts its own subtotal at zero. Starting a child call does not reset the parent's subtotal. The parent pauses while the child runs.

The decisive line is:

subtotal += nested_total(item)

In the parent, item is [3, 4]. First the call on the right finishes and supplies 7. Then the parent's addition happens. You can mentally replace that completed call with its return value: subtotal += 7.

Returning is not the same as adding. The child hands back 7; the parent's += is what includes it in the parent's total. A return ends only the call that executes it, not every waiting call.

Optional language reference: Python's return statement specifies that a return leaves the current function call with a value. This reference link was not consulted or verified in this session; the worked reasoning is included here.

Why does it stop? Numbers take the non-recursive branch. An empty list has no loop iterations, so its subtotal stays 0 and it returns 0. These are the stopping cases: no further child call is needed. With finite, non-cyclic nesting, following child lists eventually reaches numbers or empty lists.

Notice that return subtotal is after the loop. Each call must process all of its items before handing its total back.

  2. Predict nested_total([1, [2, []], 3]). Write what [] returns, what [2, []] returns, and the outer subtotal immediately before and after that child returns.
Reveal the trace and reasoning

The rule is: call the same function on the child list, wait for its result, add that result to this call's subtotal, then continue the loop.

  1. The outer call adds 1. Its subtotal is 1 when it calls the child on [2, []].
  2. That child starts at 0 and adds 2. When it meets [], it pauses at 2.
  3. The empty-list call starts at 0, has no items, and returns 0.
  4. The waiting child adds that 0: 2 + 0 = 2. Its loop ends and it returns 2.
  5. The outer call resumes: 1 + 2 = 3. It still has its final item, 3, to process: 3 + 3 = 6. It returns 6.

If you got 3, check whether you stopped the outer loop when the child returned. The child finishing lets its parent continue; it does not finish the parent.

Diagnose one tempting mistake. Suppose the list branch is changed to the following line, with everything else unchanged:

nested_total(item)  # no +=

For the same input [1, [2, []], 3], what does the outer call return now? Explain what happened to the child's result, then name the repair.

Reveal the diagnosis

The outer call returns 4: it adds only 1 and 3. The child still computes and returns 2, but the parent discards that result. Calling a function does not automatically add its return value to a local variable.

Restore subtotal += nested_total(item). The repair belongs at the caller's addition, not in a shared subtotal: each call needs its own total so it can report the sum of its own list.

4. Keep this rule · 1 minute

Each call totals its own list. Add numbers directly. For a child list, get its total and add the returned number. Return only after this call's loop is done.

This version assumes integers and finite, non-cyclic lists; it does not validate other inputs. Python also limits recursion depth, so a deeply nested list can raise RecursionError. The tiny examples here are about understanding the flow of results, not handling arbitrary input.
