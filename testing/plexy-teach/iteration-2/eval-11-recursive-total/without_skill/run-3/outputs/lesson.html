Nested lists,
one total.

Recursion is a function asking another call of itself to handle a smaller piece, then using the number that comes back.

You already know loops and returns. By the end, you’ll be able to trace a nested sum, explain where each subtotal lives, and write the function yourself.

1. Start with a loop 2. Read the function 3. Follow the calls 4. Try it 5. Make it stick
1

Keep the loop. Delegate the list.

1 minute

For a flat list, you can accumulate a total:

total = 0
for item in [2, 3, 5]:
    total += item
# total is 10

But in [2, [3, [4]], 5], an item can be a list. Adding that list directly to a number raises a TypeError.

Use two rules: if the item is a number, add it. If it is a list, get its total first, then add that returned number.

The same problem appears inside the inner list: it, too, might contain numbers and lists. So the same function can do that smaller job.

Pause: what number should replace [3, [4]]?

7. The innermost list contributes 4, so the surrounding list contributes 3 + 4. The outer list can then add 2 + 7 + 5.

2

One function, separate calls

2 minutes

The promise: give nested_total a list; it returns the sum of all numbers anywhere inside that list.

def nested_total(items):    total = 0    for item in items:        if isinstance(item, list):            total += nested_total(item)        else:            total += item    return total
  1. total = 0 starts a new local total for each call. An inner call does not reset or overwrite the outer call’s total.
  2. isinstance(item, list) chooses the path: another list gets another call; a number gets added directly.
  3. In total += nested_total(item), the caller waits for the right-hand side to return. Only then does it add the returned subtotal and move to its next item.
  4. return total is after the loop, so every item gets handled. Returning ends this call, not every call.

What makes it stop?

A list with only numbers needs no more calls. An empty list skips the loop and returns 0. These are the base cases here: work that finishes without recursion.

What makes it progress?

Each recursive call receives one contained list, not the original list again. In a finite nesting, you eventually reach numbers or empty lists.

Input agreement for this lesson: a finite, non-circular Python list containing numbers (int or float) and more such lists. Strings, tuples, and self-containing lists are outside this agreement. Very deep nesting can exceed Python’s recursion limit.

    Think first: when C starts at 0, what happens to A’s total?

    It stays at 2. Each call has its own local variables. C’s total = 0 initializes C’s total only. The calls communicate by returning numbers, not by sharing one accumulator.

    1 · Resume the caller

    In the trace, B has just returned 7. A has added it, but has not yet processed 5. What is A’s local total?

    Reveal answer and reason

    9. A’s waiting addition is 2 + 7. Its next iteration adds 5, making 14.

    2 · An empty list still returns something

    What does nested_total([[], [[]]]) return?

    Reveal answer and reason

    0. For [], the loop has no iterations and the call returns its initial 0. [[]] adds that returned 0; the outer list adds two zero subtotals.

    3 · A fresh nesting

    What does nested_total([1, [2, [], [3]], 4]) return? First work out the subtotal for [2, [], [3]].

    Reveal answer and reason

    10. The inner subtotal is 2 + 0 + 3 = 5. The outer call adds 1 + 5 + 4. Nesting changes the route, not which numbers count.

    Rebuild it, then spot the trap

    2 minutes

    Without looking back, say what belongs in the two blanks. The indentation is part of the answer.

    def nested_total(items):
    total = 0
    for item in items:
        if isinstance(item, list):
            total += __________
        else:
            total += item
    __________
    Check the blanks

    First: nested_total(item) — ask for the current inner list’s subtotal. Second: return total, outside the loop — hand back the completed total.

    Calling nested_total(items) instead would repeat the same whole-list problem without moving inward when a sublist is encountered. It would keep calling until Python raises RecursionError.

    Debugging challenge: someone moves return total inside the for loop, after the if/else. What would their function return for [2, [3], 5]?

    Reveal the bug

    2, instead of 10. On the first iteration it adds 2, then returns immediately. The remaining items never run. With the return inside the loop, an empty list would also reach the end without a return and give None, not 0.

    Keep the return aligned with for, not with the statements inside it.
