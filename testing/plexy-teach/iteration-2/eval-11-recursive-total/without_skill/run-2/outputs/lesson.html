One list at a time.

A recursive total is a loop that delegates the nested parts. The key is seeing what each call keeps and what it sends back.

11 minute · Start with a familiar loop

Same job, smaller list.

With [2, 3, 5], you loop through the numbers and add them. But a nested list contains two kinds of items: numbers to add and lists to total first.

Our running example

[2, [3, [4], 1], 5]

We want every number, at every depth, counted once. The answer is 2 + 3 + 4 + 1 + 5 = 15.

The rule for one call

  1. Start your own total at 0.
  2. For each item: add a number, or ask the same function to total a child list.
  3. Return your finished total.

That “ask the same function” step is recursion. It creates a new call; it does not restart the current one.

22 minutes · Read the contract, then the code

A list goes in. A number comes out.

nested_total(items) takes a list containing numbers and more lists, and returns one number: the total of all its numbers. We’re assuming ordinary, finite lists, with no list containing itself; strings and other types are outside this lesson.

def nested_total(items):    if not items:        return 0    total = 0    for item in items:        if isinstance(item, list):            total += nested_total(item)        else:            total += item    return total

Where it stops

if not items means “if this list is empty.” That call returns 0 immediately: an explicit base case.

A list of only numbers also finishes without any recursive calls. Each child list is deeper inside the finite structure, so eventually we reach numbers or empty lists.

Where it delegates

isinstance(item, list) checks whether the current item is a list. If it is, nested_total(item) totals that child list.

total += nested_total(item) first waits for the child’s returned number, then adds it to this call’s total.

Separate call, separate local variables. Each call has its own items, item, and total. A child starting at 0 does not erase the parent’s total. The parent pauses, remembering both its total and its place in the loop.

Notice the last return total is outside the loop. Returning inside the loop would stop after the first item, not total the whole list.

42 minutes · Trace a fresh example

Your turn: pass the totals back.

Before calculating the final answer, name what each child returns. Use paper or think it through:

nested_total([1, [], [2, [3]], 4])
  1. What does the empty child [] return?
  2. What does [3] return, and how does [2, [3]] use that number?
  3. What numbers does the outer call finally add?

Reveal the worked return chain 
[]           → 0
[3]          → 3
[2, [3]]     → 2 + 3 = 5
outer list   → 1 + 0 + 5 + 4 = 10

The outer call adds a returned 5 for the whole child list. It does not add that 5 and then separately add the child’s 2 and 3 again.

52 minutes · Rebuild the rule

The one line that makes it recursive.

Fill in the blank. This is the list branch, so item is a child list, while items is the current call’s whole list.

if isinstance(item, list):

Which expression both makes progress and gives us a number to add?
Reveal why each choice matters

Use nested_total(item). It asks for a child list’s total and returns a number to add.

nested_total(items) passes the same whole list again. On a list containing a child list, calls keep repeating the same work until Python raises a RecursionError.

item is a list here, not a numeric total. Adding that list to a number raises a TypeError.

Carry this model with you.

Loop locally. Delegate child lists. Add returned numbers. The parent waits with its own total intact; the child finishes and sends one number back.

To explain a recursive function, ask: What does one call promise? Where does it stop? How does the caller use the returned result?

Exit check: explain it without looking at the code

For [6, [2, []], 1], say what the empty list returns, what its parent returns, and what the outer list returns. Also say what the outer total is while the child is running.

Compare with a model explanation

“The empty list returns 0. Its parent [2, []] returns 2 + 0 = 2. The outer call waits with total 6, then adds the returned 2 and its last item 1, returning 9. Every call has its own total.”

A practical limit: very deep nesting can reach Python’s recursion limit. For learning the mechanism, these small finite lists are enough.
