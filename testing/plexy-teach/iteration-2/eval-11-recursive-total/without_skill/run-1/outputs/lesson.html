A 10-minute Python lesson · loops → recursion

One list, one subtotal

Recursion means a function calls itself. The useful part: each call solves one smaller piece and returns its answer to the call that asked for it.

By the end, you’ll trace a nested-list total, explain why calls stop, and write the key recursive line.

1. Start with a loop 2. Read the function 3. Trace the calls 4. Try it
0–1 minute

1. Keep the loop you already know

For [2, 3, 4, 1], a loop can add each number into total. But what about [2, [3, [4]], 1]?

The outer loop sees only three items: 2, [3, [4]], and 1. Adding that middle list directly to a number would cause a TypeError.

The new rule: If an item is a list, ask the same function to total that list. Add the number it returns, not the list itself.

So the outer calculation will become 2 + (subtotal of [3, [4]]) + 1. You don’t need to know the nesting depth in advance.

1–3 minutes

2. The whole function

Our input is a finite list containing only numbers and other lists, with no list containing itself. The function returns the sum of all the numbers, at any depth.

def recursive_total(items):
    total = 0
    for item in items:
        if isinstance(item, list):
            total += recursive_total(item)
        else:
            total += item
    return total

answer = recursive_total([2, [3, [4]], 1])
print(answer)  # 10
  1. total = 0: every call gets its own local subtotal. A child’s zero does not reset the parent’s subtotal.
  2. isinstance(item, list): choose between asking for a list’s subtotal and adding a number directly.
  3. total += recursive_total(item): the caller waits. The child finishes, returns a number, and only then does the caller add it and continue its loop.
  4. return total: after the loop, send this call’s subtotal back to its caller. Notice that return is outside the loop.

What makes it stop?

Numbers take the else branch: no new call. An empty list [] makes the loop run zero times and returns 0. These are the simple stopping cases; this version needs no separate if items == [].

Each recursive call works on a child list deeper inside the finite input. Eventually there are only numbers or empty lists, so calls finish and their results travel back outward.

3–6 minutes

3. Watch the caller wait, then resume

Trace recursive_total([2, [3, [4]], 1]). We’ll label the calls A, B, and C—they all run the same function, with different inputs and separate totals.

Reveal the reasoning after predicting

B returns 7: its own 3 plus C’s returned 4. The outer 2 and 1 belong to A’s input, not B’s. The 4 is included once inside B’s 7; A does not add it again separately.

6–9 minutes

4. Work one without the trace

Use a scratchpad. For [1, [2, []], [3, [4]], 5], write the deepest returns first:

  1. What does the call on [] return?
  2. What do the calls on [2, []] and [3, [4]] return?
  3. Replace each child list with its returned number. What does the outer call return?

Compare with the worked solution

[] → 0, so [2, []] → 2 + 0 = 2.

[4] → 4, so [3, [4]] → 3 + 4 = 7.

The outer call adds 1 + 2 + 7 + 5 = 15. Check against the individual numbers: 1 + 2 + 3 + 4 + 5 = 15. Empty lists contribute nothing.

Now rebuild the key line

Without looking above, say what belongs in the blank:

if isinstance(item, list):
    total += __________
else:
    total += item
Reveal the line and explain it

recursive_total(item). Ask for the subtotal of this child list, then add its return value to this call’s total.

Not recursive_total(items): that would call the function again on the same whole list whenever it finds a list item, so it would not make progress. Not total += item: that attempts to add a list, not its subtotal.

9–10 minutes

5. The one-minute exit check

Explain aloud: “Each call totals ______. When it reaches a child list, it ______. When the child returns, it ______.”

Compare your explanation

Each call totals its own input list. At a child list, it calls the same function and waits. When the child returns a number, it adds that number to its local total and continues its loop.

Predict these before opening the answers: [], [[], [[]]], and [-2, [5]].

Check the edge cases

[] → 0; [[], [[]]] → 0, because every child returns 0; [-2, [5]] → 3, because ordinary addition still applies to negative numbers.

Takeaway: You don’t need to hold every depth in your head. Track one call’s local total, trust a child call to return its subtotal, then resume.

Scope note: this example is for finite, non-cyclic lists of numbers. Very deep nesting can hit Python’s recursion limit; a list containing itself does not reach a stopping case.
